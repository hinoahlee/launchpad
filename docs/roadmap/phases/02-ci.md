# Phase 2 — Continuous integration

**Goal:** every PR is checked automatically, and `main` can only receive green changes.
**You'll need:** nothing new until 2.4 (Renovate). **Cost:** $0 (free Actions minutes on private repos are enough).

### 2.1 CI workflow
- **Build:** `.github/workflows/ci.yml` on `pull_request` and `push` to `main`: cached install, then
  `pnpm verify`. `concurrency` cancels outdated runs; minimal `permissions`.
- **Why:** the same command you run locally, run on a clean machine for every change.
- **Terms:** workflow, job, step, runner, cache, `GITHUB_TOKEN`.
- **Done when:** this PR shows a green check.

### 2.2 Required checks
- **Build:** add the CI check to the `main` ruleset (via `gh api`). Demo: push a lint error to the PR, show the
  merge is blocked, then fix it.
- **Why:** turns "please run the tests" into a rule nobody can skip, including you.
- **Terms:** status check, required check, branch protection.
- **Done when:** you saw the blocked merge button.

### 2.3 Build the image in CI
- **Build:** a job that builds the Docker image on every PR (no push), with Buildx and the GitHub Actions cache.
- **Why:** catches a broken Dockerfile before it reaches a deploy.
- **Terms:** Buildx, build cache, cache hit.
- **Done when:** a second run is visibly faster from cache.

### 2.4 Dependency updates
- **Build:** `renovate.json` (weekly, grouped, aware of the pnpm catalog); Dependabot security alerts on.
- **Why:** outdated dependencies are the most common way apps get vulnerable; small regular updates are cheap.
- **Terms:** semantic versioning (semver), supply-chain attack, CVE.
- 🧑 **You:** install the Renovate GitHub app on this repo only.
- **Done when:** Renovate's onboarding PR appears.
